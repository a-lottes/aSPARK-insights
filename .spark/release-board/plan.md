## 1. Architecture Decision

- **Context:** The spec commits a JSON-only, honesty-bounded map from every real git tag (A5) **and** the open window since the latest tag as a distinguishable pseudo-release (A4/C6), to the `.spark/<feature>/` directories in each range plus unattributed commits (A7), plus each artifact's header-table `Status`/`Date` (US-2). Three hard constraints bind the design: (1) AC-1.8/NFR-3 — the pseudo-release's git figures MUST be `gitboard.board.build_board()`'s own result, reused verbatim, never recomputed; (2) A6/A8/A9 — "one release, one feature" is false on this repo's own `v0.3.0` (three members) and a trailing docs commit routinely lands in the *next* range, so membership is decided purely by changed paths per range; (3) ADR-2/no-second-git-parser — new git plumbing only *extends* `gitread.py`'s established subprocess seam. This feature touches **no graph and no `GraphPort`** at all (confirmed: `board.py`/`gitread.py` import neither `aspark_graph` nor `ports/`), so the constitution's "GraphPort is the only seam" and "never mock the sibling graph" constraints are satisfied vacuously — recorded, not assumed.

- **Decision (the open calls this plan makes):**
  1. **Shape = a new `gitboard/releasemap.py` shared core (`build_release_map(repo_root, as_of) -> dict`) with one thin CLI adapter (`insights releases`)** — the same "shared core, two thin adapters" house pattern, living in the `gitboard/` package (not a `ports/` member: git is always-local, no version pin, no null-adapter state — the `git-native-mid-cycle-board`/`measurement-honesty` precedent).
  2. **New git plumbing extends `gitread.py`, not a new module:** `list_tags_topo_order` (tags oldest-first by their target commit's position in `git rev-list --topo-order` from HEAD, never `--sort=creatordate` — NFR-7 demands topology, not wall-clock), and one bounded `git log <range> --format=%h%x1f%s -- <pathspec>` per (release, feature-dir) for membership (A7). Same fixed-argument-vector, no-identity-field discipline already established.
  3. **The pseudo-release reuses `build_board()` verbatim — no signature change.** `build_board()` already returns commit count (`commits.value`), elapsed days (`days_since_tag`), work-type mix (`work_types`), branches (`branches`), and the resolved latest tag (`provenance.resolved_tag`). The pseudo-release entry copies those figure keys through unchanged and reads `provenance.resolved_tag` to fix the `<latest-tag>..HEAD` membership range — the *identical* range `build_board()` counted over. Only `members`/`unattributed` (which `build_board()` never computes — its docstring says it "never touches `.spark/`") are computed here, over the feature's own **unbounded** per-range `git log`, never `build_board`'s NFR-4-bounded `shown` list.
  4. **Artifact status = a pure `gitboard/artifactstatus.py` (`read_artifact_status(path) -> dict`), a fixed line-scan of the first pipe-table block only.** Scan from the top; the first maximal run of consecutive `|`-leading lines is the header table; within it, a row whose first cell is exactly `**Status**` (resp. `**Date**`) yields the trimmed second cell verbatim. No match → `{"status": null, "reason": "<specific cause>"}`. Deliberately not tolerant across formats (AC-2.3 wants an honest null, not a best-effort guess). Read is bounded — stop at the first line after the table block ends (NFR-5), never the whole file.
  5. **`.spark/` feature-dir enumeration is validated as untrusted (NFR-2):** each `Path.iterdir()` entry is kept only if it is a real directory whose resolved path stays under `<repo>/.spark/` and whose name contains no `/`, no `..`, and no leading `-` (a symlink escaping the root, or a flag-shaped name, is silently excluded — it is not a valid feature directory, so exclusion is honest degradation, not an error).
  6. **CLI = one subcommand `releases` with `--repo`, `--as-of` (required), `--format json` (only value this cycle — §6 excludes HTML), `--output` (accepted for flag-parity with `board`; nothing is written in JSON mode — mirrors `board`'s own inert-`--output` precedent).** `--as-of` is required and validated up front (reused `InvalidAsOfError`), since the pseudo-release's `build_board()` call needs it.
  7. **Test fixtures = hand-built synthetic git repos as the primary substrate** (mirroring `git-native-mid-cycle-board`'s `repo_notags`/`repo_over50`), **plus one real-history smoke test.** The pseudo-release's count/days move with every future commit to HEAD, so pinning "6 commits since v0.5.0" is brittle — synthetic fixtures own all count-pinned assertions. Real history owns only assertions that survive growth: AC-1.2's exact three-member `v0.3.0` (the `v0.2.0..v0.3.0` range is *frozen* — immutable past history — so it is safely pinnable) and structural invariants on the pseudo-release (exactly one, `tag:null`, `previous_tag` = latest real tag).

- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | A `GitReleasePort` under `ports/` | `ports/` = sibling-system seams with a version pin + null-adapter state; git has neither. Same ruling that kept `gitboard`/the `measurement-honesty` probe out of `ports/`. |
  | Recompute "commits since latest tag" independently for the pseudo-release | Forbidden by AC-1.8/ADR-0 — the exact second derivation §6 keeps out of scope. Reuse `build_board()` verbatim. |
  | Additive change to `build_board()` to expose the range/tag | Unnecessary — `provenance.resolved_tag` already exposes the tag and the figures are already returned; touching a stable export for nothing violates NFR-3's "no breaking change." |
  | A new tag-enumeration module | `gitread.py` is the established git seam and this is a natural superset, not a second parser (ADR-2). |
  | Order tags by `--sort=creatordate` / `git tag --list` default | Violates NFR-7 (topology, not wall-clock/creation order). Order by target-commit position in `git rev-list --topo-order`. |
  | Attribute a commit by matching its subject text to a dir name | AC-1.3/A7 forbid it — `26e7f95` names "snapshot-report" while touching none of its files. Path-only attribution. |
  | Assume one-release-one-feature | A8: false on `v0.3.0` (three members). Per-(release, feature-dir) membership from the start. |
  | Tolerant/best-effort artifact-table parsing across drift | AC-2.3 requires honest `null`+reason on any non-match, not a guess. Fixed line-scan for `| **Status** |`. |
  | Pin counts against live repo history | The pseudo-release count changes on the next commit. Synthetic fixtures for counts; real history only for frozen ranges + invariants. |

- **Consequences:** *Easier* — no graph dependency at all (the constitution's graph constraints are vacuous; the house "never mock git, use real repos" convention still applies and is honored); CLI parity and the pseudo-release's identity-free guarantee are structural via `build_board()` reuse; the artifact parser is a small pure unit. *Harder* — N feature-dirs × N ranges bounded `git log` calls (many, but each fixed-vector and cheap); the A9 "a feature reappears as a minor member of the release *after* its own" output is correct-but-surprising and must be asserted as intended, not filtered; the header-table parser must degrade honestly across the real drift documented in A3 across 7 cycles.

## 4. Test Strategy

Real git repos throughout — git is never mocked (the house convention; the sibling `aspark-graph` is not involved at all here, so its no-mock rule is moot). Synthetic `tmp_path` fixtures own every count-pinned assertion; this repo's own frozen history owns the immutable-range and invariant assertions.

- **US-1 (membership/pseudo-release) — unit + integration.** `test_releasemap_cli.py`: AC-1.1 one entry per tag, AC-1.4 zero-tags empty+reason exit 0, AC-1.5 hostile `--repo` exit 1, AC-1.7 byte-identical repeat, AC-1.10 `tag` field. `test_releasemap_membership.py`: a synthetic fixture reproducing the `v0.3.0` three-member shape (A8) **and** the A9 trailing-docs-commit-in-next-range pattern **and** the AC-1.3 adversarial subject-names-a-dir-it-didn't-touch case, plus an unattributed `.spark/BACKLOG.md`-only commit. `test_releasemap_pseudo.py`: AC-1.8 figure keys byte-equal to a direct `build_board` call, AC-1.9 true-zero (present, empty) vs no-tag (absent), AC-1.10 `tag:null`.
- **US-2 (artifact status) — unit.** `test_artifactstatus.py`: AC-2.1 present Status extracted verbatim, AC-2.2 missing file → `"file not found"`, AC-2.3 malformed/absent-Status/bad-encoding → null+specific reason, AC-2.4 only the first pipe-table block read — including the real A3 drift shapes (`###`-nested field, off-format heading) each degrading honestly.
- **US-3 (pointers) — unit.** `test_releasemap_pointers.py`: real-tag chain endpoints null, pseudo-release `previous_tag`=latest real tag / `next_tag`=null, no chaining to the pseudo-release.
- **Security — unit.** `test_releasemap_security.py`: full hostile-`--repo` checklist + malicious/symlink `.spark/` entry, fixed-vector assertion (NFR-2).
- **Privacy — integration.** `test_releasemap_integration.py`: a real `Co-Authored-By` commit, scan JSON for any identity/trailer token (NFR-3/NFR-4 — this repo's own commits carry such trailers).
- **Determinism — `test_releasemap_determinism.py`:** double-build a synthetic repo → byte-identical JSON; no wall-clock in the derivation path (all elapsed figures come from `build_board`'s `as_of`-relative arithmetic, NFR-5/NFR-7).
- **Real-history smoke — `test_releasemap_integration.py`:** AC-1.2's frozen `v0.3.0` three members + structural invariants only, no HEAD-dependent count pinned.
- **NFR-6 (accessibility):** N/A this cycle by design — no HTML surface ships (§6).

## 5. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Tag topology order is subtle — a tag not reachable from HEAD has no position in `rev-list --topo-order HEAD` | Medium (a tag silently mis-ordered or dropped) | Order by target-commit position in `git rev-list --topo-order HEAD`; this repo is linear main-only so all tags are reachable; an unreachable tag is disclosed (ordered last with a reason), never silently dropped — asserted in T1. |
| The A9 "a feature reappears as a minor member of the release after its own" output reads as a bug | Medium (a reviewer/QA files it as wrong) | It is correct per A7/A9 (path-only attribution) and is asserted as *intended* in T3, with the spec IDs cited, not filtered out. |
| N feature-dirs × N ranges `git log` calls grow with history | Low (latency only; each call bounded/fixed-vector) | Bounded per call; no performance budget set (constitution §4 leaves it open); revisit only if a real repo makes it slow. |
| Header-table drift across 7 real cycles defeats the fixed parser | Medium (a real status shown as null) | AC-2.3 makes null+reason the *correct* honest outcome, not a failure; T6 tests the real A3 drift shapes so degradation is proven, not hoped. |
| `build_board()`'s output shape changes underneath the verbatim-reuse | Medium (pseudo-release figures break) | T4 asserts the pseudo-release figure keys are byte-equal to a live `build_board` call, so any upstream shape change fails a test rather than silently drifting. |
| A maliciously-named/symlinked `.spark/` entry escapes the repo root | High (NFR-2 breach / arbitrary read) | Validate every entry (resolve under `<repo>/.spark/`, reject `/`/`..`/leading `-`); T2/T7 build the hostile fixtures and assert no escape. |

## Deviations (post-approval, fix-mode)

- **2026-08-19, `/demo-day` B1 (Major), fixed:** T2's `_list_feature_dirs` (`Path.iterdir()` on the current working tree) was the *sole* source of candidate feature names, but `git log <range> -- .spark/<name>/` (T3) already scores historical membership correctly regardless of what's on disk *now* — the candidate list was silently narrower than what membership could actually detect. A feature directory renamed, deleted, or that only ever existed on a non-current branch was invisible to every release it ever shipped in, its real commits reclassified as `unattributed` with no error. Fixed by adding `gitread.list_ever_touched_spark_feature_names` (one `git log --all --name-only -- .spark/` call, extracting every first-path-segment ever touched on any ref) and unioning it with the existing working-tree listing in a new `_all_feature_names`, each name individually validated (NFR-2) regardless of source. Small, obvious correction within the existing architecture — no new module, no new CLI flag, no scope change; does not require a `/sprint-plan` revision. Does not manifest on the real target repo (no directory has ever been renamed, all tags are linear on `main`); confirmed unchanged output there before and after the fix. Two new regression tests: `test_a_deleted_feature_directory_still_appears_in_the_release_it_shipped_in`, `test_a_feature_only_reachable_via_a_tag_on_another_branch_still_appears` (`tests/test_releasemap_membership.py`).
