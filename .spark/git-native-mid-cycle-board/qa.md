## 1. Test Environment

- **App surface:** `insights board` CLI subcommand, `--format json` (stdout) and `--format html` (writes `<output>/.aspark-insights/board.html`, offline, no server). Rendered HTML served locally for browser inspection via `python3 -m http.server 8974 --bind 127.0.0.1`, killed at the end of the session.

Every scenario checked at desktop width; the primary scenario (`this_repo`) additionally walked at 375px with `innerWidth`/`scrollWidth`/`clientWidth` measurements and a screenshot.
- **Test data / accounts used:** 14 hand-built git repos under a scratch directory (real `git init`/`commit`/`tag`/`clone`, never mocked), plus this repo (`aSPARK-insights`) itself:
  - `repo_notags` — no tags, 3 local branches
  - `repo_zerosince` — tag at `HEAD`, 0 commits since
  - `repo_lowclassifiable` — tag + 6 commits since, 1/6 (16.7%) classifiable
  - `repo_over50` — tag + 60 commits since (NFR-4 bound)
  - `repo_zerobranches` — detached `HEAD`, 0 local branch refs
  - `repo_multibranches` — 3 branches at different ages
  - `repo_html_escape` — commit subject containing `<script>alert(1)</script> & "quotes" <b>bold</b>`
  - `repo_trailers` — commits carrying real `Co-Authored-By`/`Signed-off-by` trailers
  - `repo_shallow_clone` — `git clone --depth 3 file://...` where the tag falls outside the shallow window (no tag resolves)
  - `repo_shallow2_clone` — `git clone --depth 6 file://...` where the tag *is* within the shallow window (tests the "at least N" qualifier)
  - `repo_baddate`, `repo_badtagdate` — hand-corrupted git commit objects (committer timestamp replaced with a non-numeric token via `git cat-file`/`hash-object`/`update-ref`) to exercise "tip date cannot be read" / "tag date cannot be read"
  - Hostile `--repo` CLI matrix: empty string, `../../../etc`, absolute nonexistent path, non-git directory, corrupt `.git/HEAD`
  - `PATH` stripped of `git` (AC-1.5)

## 5. Verdict

**No.** Most of this feature is genuinely excellent — the JSON/HTML honest-null discipline across the ordinary degenerate states (no tag, true zero, sub-threshold work-type mix, >50 commits, shallow clone, zero/multiple branches, hostile `--repo`, HTML-injection subjects, identity-trailer scrubbing) held up under real, adversarial testing every single time I tried to break it, and the byte-offset block order and determinism checks came back exact. I would happily demo the happy path and the specced degenerate states right now.

But I would not sign off as `passed`, for three reasons discovered by deliberately going further than the specced scenarios (per this project's own "hostile-input checklist" and "harder edge case" house conventions):

1. **A corrupted tag date crashes the whole report (B1)**, instead of nulling the one figure AC-1.10(b) says to null — the opposite of the honest-degradation promise this entire feature exists to demonstrate.
2. **A corrupted branch tip date produces a confidently-wrong, un-flagged number (B2)** — a 56-year-old branch age with `age_reason: null` — which is precisely the "invented number" failure mode the constitution and this project's own `measurement-honesty` precedent forbid, just reached via a git behavior (silent epoch substitution) that the existing F3 fix doesn't cover.
3. **Two new color pairs measured below WCAG AA's 3:1 non-text-contrast bar (NFR-7)** — the interim-marker border (2.85:1) and, more importantly, the per-branch age bar's bare track (1.30:1) in the very common case of a just-moved branch (`age_days: 0`, fill width 0%) — reproducing, in a shape the design review didn't check, the exact contrast failure its own "Verified numbers" table used to justify cutting the activity strip.

B1 sat on a Must-story AC (US-1/AC-1.10). B2 sat on a Should-story AC (US-3/AC-3.3) but was Major severity regardless of story priority.

**Post-QA resolution (`/increment` fix-mode, 2026-08-19):** the user chose to fix all five findings plus the NFR-7 contrast failure, and confirmed B5's ambiguous intent (badge absent for unclassified commits). All six items are fixed and independently re-verified against the *exact original repro* for each — not just a new passing test, per this project's own re-verification precedent (`snapshot-report`'s F1, `release.md` §6). Root causes: B1/B2/B3 are three faces of the same underlying git quirk (an unparseable committer timestamp), handled differently by `log --format` (leaves the placeholder literal) vs. `for-each-ref` (silently substitutes the Unix epoch) — both now detected and normalized in `gitread.py`, with `board.py` also gaining local `try/except ValueError` defense-in-depth so any *other* unparseable-but-truthy date degrades one figure, never the whole report. NFR-7's fix touches the shared `render.py` `_STYLE` (the pre-existing scorecard had the identical latent `.metric-bar` contrast bug — fixed at the shared source, not duplicated) and `gitboard/report.py`'s own `_BOARD_STYLE`. Full suite: 375 passed (was 369 pre-fix; 6 new regression tests, one retargeted for B5's new behavior). I would now demo this feature, happy path and every degenerate/hostile scenario I threw at it, without reservation.
