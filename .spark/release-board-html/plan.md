## 1. Architecture Decision

- **Context:** Third HTML-rendering feature in this repo. The data source `gitboard/releasemap.py:build_release_map()` already returns everything US-1/US-2/US-3 need (`releases[]` with `tag`/`previous_tag`/`next_tag`/`members[].status`/`unattributed[]`/`commits`/`branches`/`days_since_tag`/`work_types`, plus `provenance` and a top-level `reason`) — this feature recomputes nothing (ADR-0). Two precedents exist: `render.py` (pure `render_html`, light `_STYLE`, canonical `_esc`) and `gitboard/report.py` (pure `render_board_html`, imports `_esc`/`_STYLE` from `render.py`, builds its own markup). NFR-1 asks to open the already-reserved `releases --format` enum (`choices=("json",)`) to `"html"` and activate its accepted-but-unused `--output`. A1 mandates the live aSPARK dark brand palette — this repo's **first dark theme**. Packaging constraint: the wheel packages only `src/aspark_insights` (pyproject `[tool.hatch.build.targets.wheel]`), so the repo-root `assets/aspark-logo-dark.png` is **not** readable from an installed wheel and cannot be read at render time.
- **Decision:** New module `src/aspark_insights/gitboard/releaseboard_report.py` with a pure `render_release_board_html(data: dict) -> str` (dict in, HTML out, no I/O/clock/randomness — the determinism substrate and unit-test seam) plus a thin `run_release_board_report(data, output) -> Path` writer (`release-board.html`, honoring `--output`, defaulting to `--repo`, mirroring `run_board_report`). Import `_esc` from `render.py` (the one canonical escape choke-point, NFR-2) but **not** `_STYLE` (light theme, superseded by A1). Ship a fresh `_RELEASE_BOARD_STYLE` built on `:root` CSS custom properties carrying A1's tokens. The logo is optimized once (masthead-sized, ≤30KB) and committed as a base64 string constant in a dedicated `gitboard/releaseboard_logo.py`, inlined as a `data:image/png;base64,…` URI — keeping the render function pure, deterministic, and wheel-safe with zero packaging config and zero runtime file read.
- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | Extend `report.py` with the release-board markup instead of a new module | `report.py` is scoped to the `build_board()` mid-cycle shape and its light `_STYLE`; the release-map is a different data shape and A1 mandates a different (dark) palette. Co-hosting would couple two unrelated surfaces and force light+dark tokens into one module — a new module is the same separation `render.py`↔`report.py` already keep. |
  | Read `assets/aspark-logo-dark.png` at render time (package-data / `hatch` `force-include`) | Breaks render purity and NFR-6 determinism, requires new packaging config, and adds an I/O failure path to a "pure" function that must never raise a raw traceback. A committed base64 constant needs none of that and works identically in-tree and in the wheel. |
  | Reuse `render.py`'s `_STYLE` light card vocabulary + inline hex values | A1's ruling (match the live aSPARK brand site) explicitly supersedes the light scorecard theme; inlining hex duplicates each value in 10+ places. CSS custom properties match how the real site is structured and localize every token to one `:root` block. |
  | Hardcode hex throughout instead of `:root` tokens | Deviation from prior HTML surfaces (which don't use custom properties) — recorded here as a **deliberate** deviation: A1's whole point is a token-based design system, and a 5-hue badge palette + 3-color text triad is exactly where duplicated hex rots. |
- **Consequences:** Easier — CLI↔library parity via the shared `_esc`; every token lives in one `:root` block; the render stays pure so determinism/escaping are unit-testable without git. Harder — this is the repo's first dark palette, so **every** color pair needs its own contrast proof (finding 2's `--text-muted` sits near the floor); the logo carries a one-time, manual optimization step whose committed output must be reproducible; a small new named error (`ReleaseMapUnreadableError`) is introduced for the render-shape guard (justified in §2).

## 2. Affected Components

- **NEW `src/aspark_insights/gitboard/releaseboard_report.py`** — `render_release_board_html`, `run_release_board_report`, `_RELEASE_BOARD_STYLE`, `RELEASE_BOARD_FILENAME = "release-board.html"`. Additive only (NFR-3).
- **NEW `src/aspark_insights/gitboard/releaseboard_logo.py`** — the committed base64 logo constant + a header comment naming the exact regeneration command (source asset → resize → recompress → `base64`). Keeps the blob out of the readable render module.
- **MODIFIED `src/aspark_insights/cli.py`** — `releases` subparser: add `"html"` to `--format choices`, reword `--output` help (now active for `--format html`); `_cmd_releases` branches on format (mirrors `_cmd_board`). `--format json` stdout bytes unchanged (NFR-1).
- **MODIFIED `src/aspark_insights/errors.py`** — new `ReleaseMapUnreadableError` (reason `release_map_unreadable`). **Justification:** the render-shape guard is a genuinely new failure mode (a malformed data dict reaching the renderer), *not* one of the git/spark/as-of failures NFR-1 says must stay unchanged — it is the exact mirror of `BoardUnreadableError`, itself introduced for `report.py`'s identical guard, so the constitution's "never a raw traceback" non-negotiable holds on the library entry point too.
- **REUSED unchanged** — `render.py:_esc`; `gitboard/releasemap.py:build_release_map`; `gitboard/artifactstatus.py` status shape; `store.STORE_DIRNAME`. No signature/behavior change to any existing export (NFR-3).
- **MODIFIED `pyproject.toml` + `src/aspark_insights/__init__.py`** — version `0.8.0` → `0.9.0` (new `--format html` behavior is a real behavior change, per CLAUDE.md's "a version bump is a behavior claim").
- **Dependencies:** zero new runtime deps — `base64` is stdlib; the PNG optimization runs offline, never at runtime.
- **Scoping note:** no tool file was passed to this `/sprint-plan`, so *Affected Components* was scoped by hand from the spec and a direct read of the four prior-art modules — not from a blast-radius query.

## 4. Test Strategy

- **Unit (pure `render_release_board_html`, fixture dicts — the seam that needs no git, mirroring `test_gitboard_render.py`'s `_board()` helper):** every content AC. Index ordering/counts (AC-1.1/1.2), `tag:null` discrimination + true-zero (AC-1.3/3.2), drill-down member counts + real `<table>` matrix + backtick strip (AC-2.1/2.2/2.3/2.6), unattributed verbatim + "none" (AC-2.4/2.5), empty-repo + null-with-reason (AC-3.1/3.3). Contrast is unit-tested up front with the repo's existing relative-luminance helper against every shipped dark pair (T6) — the computed floor check; `getComputedStyle` confirmation is `/demo-day`'s job.
- **Security / adversarial (NFR-2):** hostile `<script>` in commit subject, artifact status, and reason strings render inert (own hand-crafted hostile fixture, per this project's adversarial-reproduction bar — not a re-run of a report's account); the §4 hostile-input checklist on `--repo`/`--output`; the render-shape guard raises a named error, never a traceback.
- **Determinism (NFR-6):** byte-identical output for a fixed fixture across two calls, including the inlined base64 logo (`test_releaseboard_determinism.py`).
- **Integration (real git, never mocked — house rule):** one end-to-end pass rendering `build_release_map()` against a real temp-git-repo fixture reusing the `test_releasemap_*` pattern — this confirms the renderer consumes the real JSON shape. No new git-integration surface is introduced (the renderer consumes already-computed JSON), so this stays a thin smoke test, not a second git-behavior suite.
- **CLI (`test_releaseboard_cli.py`):** `--format html` writes the file and reports its path; `--format json` stdout byte-unchanged; `--output` redirects the write location.
- **Deliberately left to `/demo-day` (per NFR-5's own method, browser + `getComputedStyle`, never eyeballed):** every shipped color pair via `getComputedStyle`; 375px no-horizontal-scroll (`innerWidth`/`scrollWidth`/`clientWidth`); `<h1>`/`<h2>`/`<h3>` order by DOM byte-offset; the logo's real visual render; a genuine offline (network-disabled) load. Reason it can't be unit-only: rendered/computed style and viewport behavior are only observable in a real browser.

## 5. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Logo optimization is a manual one-time step; a non-reproducible or >30KB blob ships | An oversized/irreproducible asset inflates every page (finding 5) and breaks NFR-6 across regenerations | T8 commits the optimized PNG + the exact regeneration command in the module comment; a test asserts the committed constant decodes to ≤30KB and is present; determinism test locks the rendered bytes |
| First dark palette in the repo — hex-computed contrast may differ from rendered `getComputedStyle`; `--text-muted #6c6c8a` sits ≈3.9:1, below the 4.5:1 small-text floor (finding 2) | AA-failing body text ships if `--text-muted` reaches a `reason`/`hash`/`subject` string | T6 assigns `--text-secondary` (≈7.8:1) to all small text and pins `--text-muted` to large/non-text only; unit relative-luminance test on every pair; `/demo-day` confirms via `getComputedStyle` |
| Badge hue-by-type misread as a status pass/fail judgment at `/peer-review` | A reviewer could read green-`qa`/orange-`release` as verdict hues, violating A3/AC-4.3 | Hue is keyed to artifact type identically across all rows incl. failed/null; status value always shown as text label (never color alone); one-line `/peer-review` confirmation the matrix ships as a real `<table>`, not a div badge-list |
| Determinism leak from dict/set iteration (releasemap builds member/unattributed via set ops) | Non-byte-identical renders violate NFR-6 | Renderer iterates the `releases[]`/`members[]`/`unattributed[]` lists in given order (releasemap already sorts feature names); artifact map iterated over the fixed `_ARTIFACT_NAMES` order; determinism test guards it |
| `--output` write-path hostile input (existing `report.py`/`render.py` write patterns don't obviously validate `--output` beyond a `Path` join) | A traversal/absolute `--output` could write outside intent | T9 applies the §4 checklist to `--output`; `--repo` validation is inherited from `build_release_map`'s `ensure_git_repo`; assumption inherited from the spec that release-board's own `--repo`/`--as-of` validation holds |

**Inherited spec assumptions:** A2 (no liveness / no `datetime.now()` — satisfied structurally: the renderer reads only the passed dict, no clock); A5 (the logo asset is present at `assets/aspark-logo-dark.png` — verified on disk); the pseudo-release figures come from `build_board()` verbatim (release-board's AC-1.8) — this layer must not recompute them.
